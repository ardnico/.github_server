# 調査記録と担当の引き継ぎ

`templates/investigation.example.json` を参考に、案件ごとに `.server-ops/investigations/<case-id>.json` に記録する。実案件の記録はアクセスを制限した作業領域に保存する。担当者はチームで識別できる ID を使う。未割当は null として残し、担当の引き継ぎは実際の合意を記録する。

| 状態 | 遷移条件 |
| --- | --- |
| investigating | 対象・目的を確認し、担当者が調査を開始 |
| waiting_for_answer | 判断に必要な根拠が不足。質問、回答担当、再開条件を記録 |
| reassessing | 回答または新しい証跡を受け取り、照合を再開 |
| plan_ready | 必要な根拠が揃い、計画の版と保存先を記録 |

回答が不足していれば reassessing から waiting_for_answer に戻る。更新時は同じ案件 ID で、状態・担当の変更理由、変更者、変更日時を events に追記し、現在の担当と次の作業を更新する。共有時は担当者同士で編集を調整する。

- 観測には対象、情報源、観測時刻、結果、取得できなかった範囲を残す。元の観測時刻が不明なら null とし、受領時刻はイベント側に記録する。
- 判断には時刻、判断者、根拠となる観測 ID、保留理由を残す。受領した回答の内容と観測結果を区別する。
- 計画には作成日時、版、パスを記録する。実施した操作は既存の実行記録への参照で追跡する。
