# 調査記録と担当の引き継ぎ

`templates/investigation.example.json` を参考に、案件ごとに `.server-ops/investigations/<case-id>.json` に記録する。実案件の記録はアクセスを制限した作業領域に保存する。担当者はチームで識別できる ID を使う。未割当は null として残し、担当の引き継ぎは実際の合意を記録する。

| 状態 | 遷移条件 |
| --- | --- |
| investigating | 対象・目的を確認し、担当者が調査を開始 |
| waiting_for_answer | 判断に必要な根拠が不足。質問、回答担当、再開条件を記録 |
| reassessing | 回答または新しい証跡を受け取り、照合を再開 |
| plan_ready | 必要な根拠が揃い、計画の版と保存先を記録 |

回答が不足していれば reassessing から waiting_for_answer に戻る。更新時は同じ案件 ID で、状態・担当の変更理由、変更者、変更日時を events に追記し、現在の担当と次の作業を更新する。共有時は担当者同士で編集を調整する。

- 観測には対象、情報源、観測時刻、結果、取得できなかった範囲を残す。元の観測時刻が不明なら null とし、受領時刻は回答記録に残す。
- 判断には時刻、判断者、根拠となる観測 ID、保留理由を残す。受領した回答の内容と観測結果を区別する。
- 計画には作成日時、版、パスを記録する。実施した操作は既存の実行記録への参照で追跡する。

## 回答の受領時刻

回答で再評価を始めるとき、`answers` に回答 ID、回答者、`received_at`、`received_at_source` を記録する。受領時刻はセッションの受信イベントなど、その回答に対応する確認可能な時刻を使う。セッションの回答ターン開始時刻を代理に使う場合は、参照元にその旨とイベント ID を明記する。タイムゾーンを明示し、元の精度を維持する。受領時刻が取得できなければ両フィールドを null にし、受領時刻が不明と記録する。現在時刻や送信時刻で補わない。

- `observed_at` は回答が伝える元の観測時刻。
- `answers[].received_at` はその回答の受領時刻。
- `events[].at` は再評価や状態変更を行った時刻。回答を使ったイベントには `answer_ids` を残す。
- `plan.created_at` は計画を作成した時刻。

受領・再評価・計画作成に共通の現在時刻を一括で設定しない。受領時刻が確認できる場合は出典の時刻と一致するかを照合する。時刻不明でも計画の判断材料が揃っていれば再評価を続ける。
